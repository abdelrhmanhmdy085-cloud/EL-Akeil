## 2025-05-18 - Accessible Tab Controls with ARIA & CSS Resets
**Learning:** Using non-semantic `<div>` elements for tab navigation breaks keyboard navigation and screen reader accessibility (lacking `role="tab"`, `aria-selected`, `aria-controls`, focusability, and keyboard activation). Converting tabs to `<button type="button" role="tab">` elements requires explicit CSS resets (`background: none; border: none; font-family: inherit; font-size: inherit;`) and visible focus indicators (`:focus-visible`) to maintain visual design while enabling standard a11y navigation.
**Action:** Always wrap tabs in a container with `role="tablist"`, use semantic `<button type="button" class="tab" role="tab">` elements with `aria-controls`, `aria-selected`, and `:focus-visible` styling, associate tab panel containers with `role="tabpanel"` and `aria-labelledby`, and dynamically update `aria-selected` attributes on tab switches.
